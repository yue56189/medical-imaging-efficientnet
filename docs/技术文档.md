## 1. 项目背景与源仓库分析

### 1.1 原仓库是什么

研究对象是 GitHub 仓库
`QQ767172261/Deep-Learning_Using-Convolutional-Neural-Networks-CNNs-to-select-EfficientNet-pretrained-models-for-`。
逐个文件核实后的结论：

- 仓库**只有一个 README.md**，没有任何可运行代码、没有数据、没有配置文件；
- README 顶部明示「付费获取 QQ:767172261 微信同号；白嫖勿扰！毕业设计、代码定制、数据集获取」——
  这是一个**售卖毕业设计/定制代码的引流广告仓库**；
- README 里描述的「医疗机构收集的 CT/X光/MRI 数据集」（20000 张 CT + 10 万例 X光/MRI、
  8 种病变、png + json 分类标签）是**付费商品，仓库内并不提供**。

### 1.2 README 示例代码的问题（本项目的修正点）

| # | 原示例代码问题 | 后果 | 本项目修正 |
|---|---|---|---|
| 1 | `__getitem__` 里 `list(self.annotations.items())[idx]` | 每个样本都重建整个字典列表，10 万张图慢到不可用 | 启动时扫描一次目录，缓存样本列表（`src/dataset.py`） |
| 2 | `cv2.imread` 读出 BGR 直接喂模型 | 通道顺序错误，与 PIL/torchvision 生态不一致 | 统一用 PIL 读图并 `convert("RGB")` |
| 3 | 标签字典硬编码 5 个胸部类 | 腹部 4 类（结直肠癌/胃癌/胰腺癌/肝癌）完全没实现 | 标签由目录名自动生成，任意类别数通用 |
| 4 | 没有验证循环、没有评估指标 | 无法判断模型好坏，过拟合也发现不了 | `src/train.py` 每 epoch 验证 + `src/evaluate.py` 完整评估 |
| 5 | 没有数据增强、没有类别权重 | 医学数据普遍不均衡，易学偏 | RandomResizedCrop/翻转/旋转/亮度 + balanced 类别权重 |
| 6 | `efficientnet_pytorch` 库已停止维护 | 预训练权重获取困难、API 过时 | 改用维护中的 `timm` |

### 1.3 本项目的定位

用**公开数据集**重写整套工程：完整的数据加载、两阶段迁移学习训练、评估、
Grad-CAM 可视化，并用真实数据跑出结果。技术路线与原 README 的描述一致
（CNN/EfficientNet 预训练微调医疗影像），但工程上达到可复现标准。

## 2. 总体技术路线

```
公开数据集（Kaggle / HF 镜像 / figshare）
        │
        ▼
[下载助手] 免登录直链 + MD5 校验（scripts/download_data.py）
        │
        ▼

        │
        ▼
[数据加载] PIL 读图 → RGB → 双线性缩放 → ImageNet 归一化（src/dataset.py）
        │
        ▼
[模型] timm EfficientNet-b0，ImageNet 预训练权重（src/models.py）
        │
        ▼
[训练] 阶段一：冻结 backbone 训分类头（lr=1e-3, 3 epochs）
        阶段二：解冻全网络微调（lr=1e-4, 20 epochs, 余弦退火 + 早停）
        │
        ▼
[评估] 分类报告 / 混淆矩阵 / ROC-AUC（src/evaluate.py）
        │
        ▼
[可解释性] Grad-CAM 热力图（src/gradcam.py, src/predict.py）
```

## 6. 数据准备

### 6.1 目录规范

```
<data-root>/
├── train/<类别名>/*.jpg|png
├── val/<类别名>/*.jpg|png
└── test/<类别名>/*.jpg|png      （可选，evaluate.py 用）
```

类别名即目录名，标签索引按目录名排序自动生成；`val`/`test` 允许缺少某些类别
（自动跳过），但**训练集必须包含全部类别**。

### 6.2 下载

```bash
python scripts/download_data.py list                        # 看全部数据集
python scripts/download_data.py download mri_brain_hf --dest D:/datasets/mri_brain_raw
```

三种下载通道：

| 通道 | 认证 | 说明 |
|---|---|---|
| Kaggle CLI | 需要 `~/.kaggle/kaggle.json` | 数据集最全 |
| HF 镜像（hf-mirror.com） | **免登录** | huggingface.co 直连不通时的替代，多线程直链 |
| figshare 直链 | 免登录 | 带 MD5 校验；部分网络会被服务端 403 |

### 6.3 划分

```bash
# 场景 A：数据集自带 Training/ 和 Testing/（如 Brain Tumor MRI）
python scripts/make_splits.py --src D:/datasets/mri_brain_raw \
    --dst D:/datasets/mri_brain --train-from Training --test-from Testing --val-ratio 0.15

# 场景 B：数据集只有扁平的 <类别>/*.img（如 navoneel 253 张 MRI）
python scripts/split_dataset.py --src data/raw/mri --dst data/mri --ratios 0.7 0.15 0.15
```

两个脚本都是**分层 + 固定种子**，可复现。

### 6.4 已知数据陷阱（重要）

1. **Kaggle 肺炎数据集的 val 只有 16 张**（8 NORMAL + 8 PNEUMONIA）。
   直接用它验证，指标波动极大、基本没意义。正确做法：从 train 重新切 val，
   test 留作最终评估（即场景 B 或 `make_splits.py`）。
2. **患者级数据泄漏**：NIH ChestX-ray14 等大数据集里同一患者有多张图像。
   随机划分会让同一患者的图像同时出现在 train 和 test，指标虚高。
   严格做法是按 Patient ID 划分。本实验用的 Brain Tumor MRI 为公开均衡集，
   按官方 train/test 划分，未做患者级核验（数据说明未提供患者 ID），此为该数据的固有局限。
3. **不要把增强用在 val/test**：增强只属于训练集，否则等于“考前泄题”。

## 7. 模型与训练方法

### 7.1 为什么是 EfficientNet

EfficientNet（Tan & Le, 2019）的核心是**复合缩放**：同时优化深度/宽度/分辨率
三个维度，而不是只堆深度。在同等参数量下精度/效率优于 ResNet。
b0 只有 5.3M 参数，ImageNet top-1 77.1%，是迁移学习的性价比之选；
显存/时间充裕可上 b2/b3（本项目代码 `--model efficientnet_b3` 即可切换）。

### 7.2 两阶段迁移学习

| 阶段 | 策略 | 学习率 | epochs | 目的 |
|---|---|---|---|---|
| 一 | 冻结 backbone，只训分类头 | 1e-3 | 3 | 随机初始化的分类头快速对齐预训练特征，不破坏 backbone |
| 二 | 解冻全网络 | 1e-4 | 20 | 小学习率精细微调，余弦退火 + 早停（patience=5） |

直接全网络一把梭（原 README 的做法）在大学习率下容易**冲垮预训练特征**，
两阶段是更稳的工程惯例。

### 7.3 数据增强与医学禁忌

训练集增强：`RandomResizedCrop(0.85~1.0)` → `RandomHorizontalFlip` →
`RandomRotation(15°)` → `ColorJitter(0.1)` → `Normalize(ImageNet)`。

两条医学影像纪律：

1. **不做垂直翻转**：X 光/MRI 有解剖方位（上/下、左/右），垂直翻转会产生
   现实中不存在的图像，模型会学到错误先验；
2. **双线性插值而非双三次**：双三次在锐利边缘（骨骼、植入物、肿瘤边界）上
   会产生振铃伪影（ringing），双线性更稳。

### 7.4 其他关键设置

- **类别权重**：`w_c = N / (K * count_c)`（sklearn balanced 策略），自动处理不均衡；
- **优化器**：AdamW（weight_decay=1e-4）；
- **混合精度**：`--amp`（仅 GPU），省显存提速；
- **随机种子**：`--seed 42`，train/val 划分与训练可复现；
- **模型选择**：按验证集 **macro-F1**（不是 accuracy）存 best——医学场景少数类
   漏诊代价高，macro-F1 对每个类一视同仁。

### 7.5 超参数速查

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--model` | efficientnet_b0 | timm 任意模型名 |
| `--img-size` | 224 | EfficientNet-b0 的原生分辨率 |
| `--batch-size` | 32 | 显存不足可降 16 |
| `--freeze-epochs` | 3 | 阶段一轮数 |
| `--epochs` | 20 | 阶段二轮数 |
| `--lr-head` / `--lr` | 1e-3 / 1e-4 | 两阶段学习率 |
| `--patience` | 5 | 早停耐心 |
| `--amp` | 关 | GPU 时开启 |

## 8. 实验结果

> 以下为本次在本机用 Brain Tumor MRI 数据集真实跑出的结果（非引用、非估算）。
> 训练于 2026-10-19 完成，产物存档在 `results/`。

### 8.1 实验配置

| 项 | 值 |
|---|---|
| 数据集 | Brain Tumor MRI（masoudnickparvar），4 类 |
| 划分 | train 4,760 / val 840 / test 1,600（val 从官方 train 分层切 15%，test 用官方 test） |
| 模型 | timm `efficientnet_b0`，ImageNet 预训练，4.0M 参数 |
| 训练 | 阶段一冻结 2 epochs（lr=1e-3）→ 阶段二解冻 8 epochs（lr=1e-4），AdamW，余弦退火，早停 patience=5 |
| batch size | 64 |
| 设备 | **CPU**（22 核），无混合精度，总耗时 **40 分 22 秒** |
| 类别权重 | 全 1.0（四类本就均衡，1400/1400/1400/1400） |

### 8.2 验证集过程（train.py 输出）

| epoch | 阶段 | train_loss | val_loss | train_acc | val_acc | val macro-F1 |
|---|---|---|---|---|---|---|
| 1 | freeze | 2.3445 | 1.5983 | 0.4189 | 0.5643 | 0.5664 |
| 2 | freeze | 1.3134 | 1.3538 | 0.6265 | 0.6167 | 0.6147 |
| 3 | finetune | 0.5087 | 0.3663 | 0.8513 | 0.8881 | 0.8872 |
| 4 | finetune | 0.1665 | 0.2696 | 0.9426 | 0.9155 | 0.9147 |
| 5 | finetune | 0.0999 | 0.2322 | 0.9653 | 0.9345 | 0.9337 |
| 6 | finetune | 0.0569 | 0.2031 | 0.9786 | 0.9452 | 0.9450 |
| **7** | finetune | 0.0400 | 0.1916 | 0.9878 | **0.9536** | **0.9533** ← best |
| 8 | finetune | 0.0281 | 0.1980 | 0.9908 | 0.9452 | 0.9452 |
| 9 | finetune | 0.0311 | 0.1647 | 0.9905 | 0.9524 | 0.9523 |
| 10 | finetune | 0.0296 | 0.1759 | 0.9897 | 0.9476 | 0.9474 |

最佳模型 = 第 7 epoch（按 val macro-F1 选择）。完整曲线见 `results/training_curves.png`。

### 8.3 Test 集最终指标（1,600 张，模型未见过）

| 指标 | 值 |
|---|---|
| **Accuracy** | **0.9144** |
| **Macro precision / recall / F1** | 0.92 / 0.91 / 0.91 |
| **Macro ROC-AUC（OvR）** | **0.9821** |

分类报告（`results/test_metrics.json`）：

| 类别 | precision | recall | F1 | support |
|---|---|---|---|---|
| glioma | 0.99 | **0.77** | 0.87 | 400 |
| meningioma | 0.91 | 0.90 | 0.90 | 400 |
| notumor | 0.90 | 0.99 | 0.94 | 400 |
| pituitary | 0.89 | 0.99 | 0.94 | 400 |

混淆矩阵（`results/confusion_matrix.png`）显示错分集中在两处：
**glioma → meningioma 36 张、glioma → notumor 33 张**（共 92/400 张 glioma 被错分）。
这是该数据集的公认难点：胶质瘤与脑膜瘤在 T1 加权像上形态相近。
ROC 曲线见 `results/roc_curves.png`；各类 OvR-AUC：
glioma 0.950 / meningioma 0.986 / notumor 0.994 / pituitary 0.999——
glioma 的 AUC 明显低于其他三类，与它 recall 垫底互为印证（排序能力和硬分类同时吃亏）。

### 8.4 val 95.3% vs test 91.4% 的差异说明（重要）

val 参与了**模型选择**（早停 + best 挑选），因此天然偏乐观；
test 从头到尾未参与任何决策，91.4% 才是对泛化性能的无偏估计。
两者差 ~4 个点属于正常范围，不是过拟合事故（train/val gap 仅 ~3.5 个点）。

### 8.5 Grad-CAM 可视化（`results/gradcam_examples/`）

- `pituitary_Te-pi_286_gradcam.png`：预测 pituitary，置信度 1.0000，热力图聚焦在鞍区病灶；
- `glioma_Te-gl_277_gradcam.png`：真实 glioma，**错判为 notumor（置信度 0.966）**——
高置信度错判样本，与 8.3 节中 glioma recall 偏低互为印证。
  这类样本正是医学 AI 需要人工复核的典型场景。

### 8.6 结论与局限

**结论**：两阶段迁移学习在该数据集上 work——解冻后第一个 epoch val acc 就从
61.7% 跳到 88.8%，最终 test 91.4% / AUC 0.9821。全流程（下载→训练→评估→可视化）
可复现，代码对任意 ImageFolder 结构数据集零改动复用。

**局限**（如实声明）：
1. CPU 训练、仅 10 epochs、未做学习率搜索——**这不是调优上限，是可行性验证**；
   有 GPU 后 `--amp --epochs 30` 通常还能再涨；
2. 数据集无患者级 ID，无法排除同患者多图跨划分的泄漏（公开均衡数据集固有局限）；
3. glioma 是明确短板，后续可做类别加权（本实验权重全 1 没帮上它）、
   难例挖掘或更大模型（efficientnet_b2/b3）；
4. 单模型单数据集，结论不外推。

## 9. 评估方案

`src/evaluate.py` 输出四件套到 `runs/<时间戳>/eval/`：

1. **metrics.json**：accuracy、macro precision/recall/F1、每类 ROC-AUC、混淆矩阵原始数据；
2. **confusion_matrix.png**：带类别名的混淆矩阵热图；
3. **roc_curves.png**：one-vs-rest ROC 曲线（含每类 AUC）；
4. **分类报告**：终端直接打印。

指标解读纪律（写进报告时遵守）：

- accuracy 会骗人（类别不均衡时尤其），必须同时报 macro-F1 和每类 recall；
- 医学场景优先看**漏诊率**（对应 recall/敏感度）；
- ROC-AUC 对阈值不敏感，适合作辅助证据；
- 小验证集（<100 张）的指标只配定趋势，不配写结论。

## 10. 推理与 Grad-CAM

```bash
# 单图
python src/predict.py --checkpoint runs/xxx/best.pt --image patient_mri.jpg

# 整个目录
python src/predict.py --checkpoint runs/xxx/best.pt --image data/test/glioma --output outputs/glioma
```

每张图输出：预测类别 + 置信度 + `_gradcam.png`（jet 伪彩色热力图叠加原图）。
热力图高亮区域即模型分类依据的像素——论文里用来证明模型“看的是病灶而不是水印/黑边”。

Grad-CAM 实现要点（`src/gradcam.py`）：在 timm EfficientNet 的 `conv_head`
（最后一个卷积阶段）注册 forward/backward hook，对目标类别分数反向传播，
`CAM = relu(Σ 通道梯度空间均值 × 特征图)`，再上采样叠加。

## 11. 已知限制与未验证事项（如实声明）

1. **本实验用 CPU 训练**：速度慢但结果有效；未在 GPU 上验证 `--amp` 路径
   （代码按标准 API 编写，未经实跑）；
2. **数据集无患者级 ID**：无法排除同一患者多张图像跨划分的泄漏可能，
   这是公开均衡数据集的固有局限；
3. **Kaggle 通道未实跑**：Kaggle 下载需要用户自己的 API 凭证，本次只用免登录通道；
   figshare 直链在本机网络被 403（链接本身有效，换网络环境可用）；
4. **代码验证边界**：`split_dataset.py` 的划分逻辑用假数据冒烟测试通过（数量精确）；
   `src/` 下的训练/评估代码在本次真实训练中完整跑通；`--amp` 与 CUDA 路径未测；
5. **单数据集单模型**：结论不外推到其他模态/其他模型。

## 12. 扩展方向

- **多模态**：按 README 的设想，CT/X光/MRI 分别训练各自模型，再做一个路由/
  集成层（本项目代码对三个模态的数据集零改动复用）；
- **换模型**：timm 里 `--model efficientnet_b2`、`convnext_tiny`、`vit_small_patch16_224`
  一行切换，对比实验；
- **多标签**：NIH ChestX-ray14 需把 CrossEntropy 换成 BCEWithLogits + 多热标签；
- **测试时增强（TTA）** + **模型集成**：通常还能再涨 1~2 个点；
- **患者级划分**：有大数据集时按 Patient ID 划分，论文级严谨；
- **部署**：`torch.onnx.export` 导出 + onnxruntime 推理，或 Gradio 做个演示页。
