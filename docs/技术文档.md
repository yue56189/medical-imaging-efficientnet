## 1. 项目背景

### 1.1 项目来源

本项目的技术路线源于一个公开的 GitHub 项目
`QQ767172261/Deep-Learning_Using-Convolutional-Neural-Networks-CNNs-to-select-EfficientNet-pretrained-models-for-`
（主题：使用卷积神经网络选择 EfficientNet 预训练模型，对 CT、X 光、MRI 医疗影像数据集进行微调）。

该仓库以 README 的形式给出了一套完整的技术思路框架，包括：

- 数据集的目录组织方式：按模态（CT / X 光 / MRI）与疾病类别分层，附 json 格式分类标签；
- 迁移学习流程：加载 EfficientNet 预训练权重，替换分类头，在医疗影像数据上微调；
- 优化方向的讨论：数据增强、按模态分别建模、模型剪枝与量化。

受这一思路启发，本仓库围绕同一技术路线开展了独立的工程实现：使用**公开数据集**与
**开源工具链**，从数据获取、加载、训练、评估到可解释性可视化，完成了全流程的工程化
与实验验证。对医学影像分类任务的方法学支撑见第 13 节文献 [C1][C3][E7][E8]。

### 1.2 示例代码的局限与对应的工程改进

该 README 中的示例代码以演示 API 调用为主，距离可复现的实验代码尚有差距。
下表逐条列出其局限与本项目的改进：

| # | 示例代码的局限 | 后果 | 本项目改进 |
|---|---|---|---|
| 1 | `__getitem__` 中每个样本都执行 `list(annotations.items())[idx]` | 样本量增大后数据加载耗时急剧上升，十万级图像不可用 | 初始化时扫描一次目录并缓存样本列表（`src/dataset.py`） |
| 2 | 使用 `cv2.imread` 读取图像后直接送入模型 | BGR 通道顺序与 PIL / torchvision 生态不一致，引入通道错乱风险 | 统一用 PIL 读图并 `convert("RGB")` |
| 3 | 标签字典硬编码 5 个胸部类别 | 无法覆盖腹部病变类别，扩展性差 | 标签索引由目录名自动生成，支持任意类别数 |
| 4 | 无验证循环、无评估指标 | 无法监控过拟合，模型好坏无依据 | 每 epoch 验证 + 独立 test 评估（报告 / 混淆矩阵 / ROC） |
| 5 | 无数据增强、无类别不平衡处理 | 医学数据普遍不均衡，模型易偏向多数类 | 医学友好的增强策略 + balanced 类别权重 |
| 6 | 依赖已停止维护的 `efficientnet_pytorch` | 预训练权重获取与 API 兼容性差 | 改用维护中的 `timm` 模型库 |

### 1.3 本项目的定位

用**公开数据集**重写整套工程：完整的数据加载、两阶段迁移学习训练、评估、
Grad-CAM 可视化，并用真实数据跑出结果。技术路线与原 README 的描述一致
（CNN/EfficientNet 预训练微调医疗影像），但工程上达到可复现标准。

        │

5. **有同任务的公开对照**：多篇中文研究在同一数据集上报告了 97%～99% 的准确率
   [C5][C6]，可作为本项目 91.4% 的参照系——这些工作普遍采用了更复杂的网络结构
   （注意力机制、联邦学习、动态卷积）或更长的训练配置，与本项目的轻量基线形成互补。

## 6. 数据准备

### 6.1 目录规范

```
<data-root>/
├── train/<类别名>/*.jpg|png
├── val/<类别名>/*.jpg|png
└── test/<类别名>/*.jpg|png      （可选，evaluate.py 用）
```

类别名即目录名，标签索引按目录名排序自动生成；`val`/`test` 允许缺少某些类别
（自动跳过），但**训练集必须包含全部类别**。

### 6.2 下载

```bash
python scripts/download_data.py list                        # 看全部数据集
python scripts/download_data.py download mri_brain_hf --dest D:/datasets/mri_brain_raw
```

三种下载通道：

| 通道 | 认证 | 说明 |
|---|---|---|
| Kaggle CLI | 需要 `~/.kaggle/kaggle.json` | 数据集最全 |
| HF 镜像（hf-mirror.com） | **免登录** | huggingface.co 直连不通时的替代，多线程直链 |
| figshare 直链 | 免登录 | 带 MD5 校验；部分网络会被服务端 403 |

### 6.3 划分

```bash
# 场景 A：数据集自带 Training/ 和 Testing/（如 Brain Tumor MRI）
python scripts/make_splits.py --src D:/datasets/mri_brain_raw \
    --dst D:/datasets/mri_brain --train-from Training --test-from Testing --val-ratio 0.15

# 场景 B：数据集只有扁平的 <类别>/*.img（如 navoneel 253 张 MRI）
python scripts/split_dataset.py --src data/raw/mri --dst data/mri --ratios 0.7 0.15 0.15
```

两个脚本都是**分层 + 固定种子**，可复现。

### 6.4 数据划分的注意事项

1. **Kaggle 肺炎数据集的 val 仅 16 张**（8 NORMAL + 8 PNEUMONIA）。
   在此规模下验证指标波动极大，不具备模型选择意义。正确做法是从 train 重新切分 val，
   test 留作最终评估（即场景 B 或 `make_splits.py`）。
2. **患者级数据泄漏**：NIH ChestX-ray14 等大规模数据集中，同一患者贡献多张图像 [E6]。
   若随机划分，同一患者的图像可能同时进入 train 与 test，造成指标虚高。
   严格做法是按 Patient ID 划分。本实验使用的 Brain Tumor MRI 为公开均衡数据集，
   采用官方 train/test 划分，数据说明未提供患者 ID，无法做患者级核验，
   此为该数据集的固有局限（见 8.6 节）。
3. **数据增强只属于训练集**：对验证/测试集施加随机增强会改变其分布，
   使评估结果失去意义。

## 7. 模型与训练方法

### 7.1 为什么是 EfficientNet

EfficientNet（Tan & Le, ICML 2019）[E3] 的核心是**复合缩放**：在深度、宽度、输入分辨率
三个维度上按固定比例协同缩放，而非仅增加深度。在同等参数量下，其精度/效率优于
ResNet [E2] 等前代架构；后续 EfficientNetV2 [E4] 进一步引入 Fused-MBConv 与渐进式训练，
在速度与参数上再获改善。b0 仅 5.3M 参数（本任务替换分类头后为 4.0M），
ImageNet top-1 77.1%，是迁移学习的性价比之选；算力充裕时可升级至 b2/b3
（本项目代码 `--model efficientnet_b3` 一行切换）。ImageNet 大规模预训练 [E1]
是上述迁移策略成立的前提，而「小样本医学数据集 + 预训练微调即可达到高精度」
在 Kermany 等 [E7] 的工作中得到了早期验证，也是本项目方法学的直接依据。

### 7.2 两阶段迁移学习

| 阶段 | 策略 | 学习率 | epochs | 目的 |
|---|---|---|---|---|
| 一 | 冻结 backbone，只训分类头 | 1e-3 | 3 | 随机初始化的分类头快速对齐预训练特征，不破坏 backbone |
| 二 | 解冻全网络 | 1e-4 | 20 | 小学习率精细微调，余弦退火 + 早停（patience=5） |

若跳过第一阶段、直接以较大学习率训练全部参数（示例代码的做法），容易在初期破坏预训练特征；
两阶段策略是更稳妥的工程惯例，其中「先冻结、后微调」的有效性在多个中文医学影像
研究中得到实验支持 [C3][C8]。

### 7.3 数据增强与医学禁忌

训练集增强：`RandomResizedCrop(0.85~1.0)` → `RandomHorizontalFlip` →
`RandomRotation(15°)` → `ColorJitter(0.1)` → `Normalize(ImageNet)`。

两条医学影像纪律：

1. **不做垂直翻转**：X 光/MRI 具有确定的人体解剖方位，垂直翻转会产生
   现实中不存在的图像，模型会学到错误的空间先验；
2. **双线性插值而非双三次**：双三次插值在锐利边缘（骨骼、植入物、肿瘤边界）附近
   可能产生振铃伪影，双线性更稳健 [E10]。

### 7.4 其他关键设置

- **类别权重**：`w_c = N / (K * count_c)`（sklearn balanced 策略），自动处理不均衡；
- **优化器**：AdamW（weight_decay=1e-4）；
- **混合精度**：`--amp`（仅 GPU），省显存提速；
- **随机种子**：`--seed 42`，train/val 划分与训练可复现；
- **模型选择**：按验证集 **macro-F1**（不是 accuracy）存 best——医学场景少数类
   漏诊代价高，macro-F1 对每个类一视同仁。

### 7.5 超参数速查

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--model` | efficientnet_b0 | timm 任意模型名 |
| `--img-size` | 224 | EfficientNet-b0 的原生分辨率 |
| `--batch-size` | 32 | 显存不足可降 16 |
| `--freeze-epochs` | 3 | 阶段一轮数 |
| `--epochs` | 20 | 阶段二轮数 |
| `--lr-head` / `--lr` | 1e-3 / 1e-4 | 两阶段学习率 |
| `--patience` | 5 | 早停耐心 |
| `--amp` | 关 | GPU 时开启 |

| pituitary | 0.89 | 0.99 | 0.94 | 400 |

混淆矩阵（`results/confusion_matrix.png`）显示错分集中在两处：
**glioma → meningioma 36 张、glioma → notumor 33 张**（共 92/400 张 glioma 被错分）。
这是该数据集的公认难点：胶质瘤与脑膜瘤在 T1 加权像上形态相近，文献中亦有同样报道
[C5][C10][E8]。
ROC 曲线见 `results/roc_curves.png`；各类 OvR-AUC：
glioma 0.950 / meningioma 0.986 / notumor 0.994 / pituitary 0.999——
glioma 的 AUC 明显低于其他三类，与它 recall 垫底互为印证（排序能力和硬分类同时吃亏）。

### 8.4 val 95.3% vs test 91.4% 的差异说明（重要）

val 参与了**模型选择**（早停 + best 挑选），因此天然偏乐观；
test 从头到尾未参与任何决策，91.4% 才是对泛化性能的无偏估计。
两者差 ~4 个点属于正常范围，不是过拟合事故（train/val gap 仅 ~3.5 个点）。

### 8.5 Grad-CAM 可视化（`results/gradcam_examples/`）

- `pituitary_Te-pi_286_gradcam.png`：预测 pituitary，置信度 1.0000，热力图聚焦在鞍区病灶；
- `glioma_Te-gl_277_gradcam.png`：真实 glioma，**错判为 notumor（置信度 0.966）**——
高置信度错判样本，与 8.3 节中 glioma recall 偏低互为印证。
  这类样本正是医学 AI 需要人工复核的典型场景。

### 8.6 结论与局限

**结论**：两阶段迁移学习的有效性在本实验中得到验证——解冻后首个 epoch 验证集准确率
从 61.7% 提升至 88.8%，最终 test 91.4% / AUC 0.9821。全流程（下载→训练→评估→可视化）
可复现，代码对任意 ImageFolder 结构的数据集无需改动即可复用。

**局限**（如实声明）：
1. CPU 训练、10 个 epoch、未做学习率搜索——本实验旨在验证流程可行性，
   不构成调优上限；配备 GPU 后启用 `--amp` 并增加 epoch 数，性能仍有提升空间；
2. 数据集未提供患者级 ID，无法排除同一患者多张图像跨划分的泄漏可能，
   这是公开均衡数据集的固有局限；
3. glioma 类别性能明显偏弱，后续可从类别重加权（本实验四类本就均衡，权重均为 1，
   未能改善该类）、难例挖掘或更换更大容量模型（efficientnet_b2/b3）等方向改进 [C5][C7]；
4. 单模型、单数据集，结论不外推至其他模态或其他模型。

## 9. 评估方案

`src/evaluate.py` 输出四件套到 `runs/<时间戳>/eval/`：

1. **metrics.json**：accuracy、macro precision/recall/F1、每类 ROC-AUC、混淆矩阵原始数据；
2. **confusion_matrix.png**：带类别名的混淆矩阵热图；
3. **roc_curves.png**：one-vs-rest ROC 曲线（含每类 AUC）；
4. **分类报告**：终端直接打印。

指标解读纪律（写进报告时遵守）：

- accuracy 会掩盖类别不均衡问题，必须同时报告 macro-F1 与各类 recall；
- 医学场景优先关注**漏诊率**（对应 recall / 敏感度）；
- ROC-AUC 对分类阈值不敏感，适合作为辅助证据；
- 小规模验证集（<100 张）的指标仅可用于观察趋势，不足以支撑定量结论。

## 10. 推理与 Grad-CAM

```bash
# 单图
python src/predict.py --checkpoint runs/xxx/best.pt --image patient_mri.jpg

# 整个目录
python src/predict.py --checkpoint runs/xxx/best.pt --image data/test/glioma --output outputs/glioma
```

每张图输出：预测类别 + 置信度 + `_gradcam.png`（jet 伪彩色热力图叠加原图）。
热力图高亮区域即模型做出分类判断所依据的像素，可用于向非算法人员说明模型的关注区域
是否落在解剖/病灶位置上 [E5]。

Grad-CAM 实现要点（`src/gradcam.py`）：在 timm EfficientNet 的 `conv_head`
（最后一个卷积阶段）注册 forward/backward hook，对目标类别分数反向传播，
`CAM = relu(Σ 通道梯度空间均值 × 特征图)`，再上采样叠加。

## 11. 已知限制与未验证事项（如实声明）

1. **本实验用 CPU 训练**：速度慢但结果有效；未在 GPU 上验证 `--amp` 路径

   figshare 直链在本机网络被 403（链接本身有效，换网络环境可用）；
4. **代码验证边界**：`split_dataset.py` 的划分逻辑用假数据冒烟测试通过（数量精确）；
   `src/` 下的训练/评估代码在本次真实训练中完整跑通；`--amp` 与 CUDA 路径未测；
5. **单数据集单模型**：结论不外推到其他模态/其他模型。
